# 77math 쇼츠 제작 플레이북

인스타그램 릴스/쇼츠용 20~25초 수학·과학 콘텐츠를 기획부터 렌더링까지 직접 만든다.
소스 영상을 재편집하는 게 아니라 **matplotlib으로 그래픽을 새로 그리고, ffmpeg로 자막+엔딩을 입힌다.**

## 0단계 — 이어서 하기 전 확인
- 이미 만든 소재는 아래 "제작 완료 목록"에 있다. **겹치는 소재로 다시 기획하지 않는다.**
- 사용자가 "다음 3개" 식으로 요청하면: 웹 검색으로 트렌드 확인 → "다음 후보 소재" 목록 우선 고려 → 3개 선정 → 서사 설계 → 코드 작성 → 검증 → 자막/엔딩 합성 → 전달, 순서로 진행한다.
- 매 회차 끝나면 이 파일의 "제작 완료 목록"과 "그동안 배운 것"을 갱신한다 (사용자가 "기억해", "저장해" 라고 하지 않아도 회차가 끝나면 습관적으로 갱신).

## 1단계 — 서사 프레임워크 (심리학 근거 기반, 모든 영상에 빠짐없이 적용)

정보격차이론(Loewenstein)과 자이가르닉 효과 기반. 6단계, 총 20~25초 타이밍 기준:

| 단계 | 시간 | 심리적 기능 | 체크 |
|---|---|---|---|
| ① 훅 | 0-2초 | 정보격차를 "딱 궁금한 크기"로 연다. 화면은 반드시 처음부터 움직이고 있어야 함 (빈 화면 금지) | 질문형 또는 놀라운 주장으로 시작했는가? |
| ② 빌드업 | 2-10초 | 답을 주지 않고 격차를 더 벌린다 (자이가르닉) | 매 비트가 이전보다 더 궁금하게 만드는가? |
| ③ 긴장 피크 | 해결 직전 2-3초 | 시청자가 스스로 할 반박을 먼저 대신 말해준다 → 공감+신뢰 | "그런데 이거 트릭 아니야?" 류 문장이 있는가? **가장 빠뜨리기 쉬운 단계 — 반드시 체크** |
| ④ 해결 | 3-4초 | 격차를 한 문장으로 확실히 닫는다 (도파민 보상) | 큰 글씨, 짧은 한 문장인가? |
| ⑤ 검증 | 3-5초 | "그냥 우기는 거 아니냐"는 의심을 데이터/숫자로 차단 | 정확한 수치(실제 데이터, 시뮬레이션 횟수, 오차범위)가 있는가? 논리 퍼즐이면 "충돌 없음을 화면에서 직접 확인시키기"로 대체 |
| ⑥ 보상/CTA | 마지막 2-3초 | 다음 영상도 보고 싶게 만드는 고리 | 77math 엔딩 카드로 마무리했는가? |

**발산형 반전도 가능**: 대부분은 "수렴"이 반전(몬티홀, 생일역설)이지만, 상트페테르부르크 역설처럼 "절대 수렴 안 함" 자체를 반전으로 쓸 수도 있다. 숫자가 크지 않아도 그래프를 로그축+계단식으로 그리면 "널뛰는 패턴" 자체로 반전을 전달할 수 있다.

## 2단계 — 브랜드 스타일 (고정값, 매번 동일하게 적용)

- 해상도: 1080x1920 (9:16), 30fps, `-crf 18 -preset medium`, `-pix_fmt yuv420p`
- 배경색: `#07070c`
- 팔레트: 시안 `#00e5ff` / 초록 `#00ffa2` / 노랑 `#ffd400` / 주황 `#ff8a00` / 핑크 `#ff2d78` / 보라 `#b026ff` / 파랑 `#4d7bff` / 빨강 `#ff5555`
- 폰트: `/usr/share/fonts/opentype/noto/NotoSansCJK-Bold.ttc` (한글 필수 — 시스템 기본 DejaVu는 한글 글리프 없음)
- 엔딩 카드: 검은 배경 2초, "77math" 텍스트 중앙, 페이드인(0~0.5초)→홀드→페이드아웃(1.6~2.0초). 모든 영상 마지막에 고정으로 붙인다.
- 자막 스타일: `drawtext:box=1:boxcolor=black@0.55:boxborderw=22`, 일반 자막 fontsize 40~48, 해결/반전 자막은 52~56 + 색상 강조

## 3단계 — 기술 체크리스트 (겪었던 실수들)

1. **matplotlib 한글 깨짐**: `fm.fontManager.addfont(폰트경로)` 후 `matplotlib.rcParams["font.family"]`에 등록해야 함. 안 하면 한글 자리에 네모/경고.
2. **ffmpeg drawtext에 `%` 넣으면 텍스트가 통째로 사라짐**: `%%`로 이스케이프해도 불안정 → `drawtext=...:expansion=none:...`을 반드시 붙인다. 퍼센트 안 쓰는 자막도 습관적으로 `expansion=none` 붙이면 안전.
3. **콤마(,) 포함 텍스트**: 필터그래프 안에서는 `\,`로 이스케이프.
4. **원본 영상 워터마크 제거**: `delogo=x=:y=:w=:h=`는 텍스트만 있는 영역에선 완벽히 지워지지만, 그 위로 곡선이 지나가면 흐림 자국이 남는다. 박스를 최대한 작게(텍스트 높이만큼만) 잡아서 피해를 줄인다.
5. **성능**: 개별 needle/line을 수백 개 `ax.plot()`으로 따로 만들어 매 프레임 갱신하면 렌더링이 2~3분씩 걸린다 (뷔퐁의 바늘에서 체감). 점 수백~수만 개를 다뤄야 하면 `ax.scatter()` 하나로 벡터화해서 갱신하는 게 훨씬 빠르다 (울람 나선 방식).
6. **기하학적으로 확실하지 않은 도형(예: 사라진 정사각형 퍼즐의 정확한 좌표)은 만들기 전에 좌표를 직접 검산한다.** 확신 없으면 다른 소재로 대체하는 게 낫다 — 잘못된 시각 증명은 신뢰도를 깎아먹는다.
7. **시뮬레이션 기반 영상은 반드시 실제 이론값과 대조 검증**: 벤포드(이론 30.1% vs 시뮬 30.6%), 도박사오류(49.9:50.1), 뷔퐁(오차 0.0185) 처럼 코드 실행 결과를 실제로 확인하고 자막에 넣는다.
8. **배경음악 없음**: 소스가 무음이거나 새로 렌더링한 영상은 오디오 트랙이 없다. 매번 사용자에게 "업로드 시 트렌딩 오디오 직접 입혀야 함"을 안내한다.

## 4단계 — 제작 파이프라인

1. `pip install numpy matplotlib` (세션마다 재설치 필요할 수 있음)
2. `gen_<주제>.py` 작성 → matplotlib `FuncAnimation` + `FFMpegWriter`로 `raw_<주제>.mp4` 생성 (자막 없는 순수 그래픽)
3. 프레임 타임스탬프별로 `ffmpeg -ss <t> -frames:v 1`로 스냅샷 뽑아서 **반드시 육안 확인** (특히 시간대별 콘텐츠가 의도한 것과 맞는지 — 과거에 프레임 인덱싱 착각으로 캡션과 실제 화면이 안 맞은 적 있음)
4. `build_video<N>.sh`로 ffmpeg drawtext 자막 + 77math 엔딩 합성 → `video<N>_<주제>.mp4`
5. 최종 파일도 여러 시점 스냅샷으로 자막 위치/타이밍 확인 후 전달

7. 벤포드의 법칙
8. 도박사의 오류
9. 제논의 역설 (무한급수)
10. 뷔퐁의 바늘 (원주율 추정)
11. 힐베르트의 무한 호텔
12. 상트페테르부르크 역설

## 다음 후보 소재 (아직 안 만듦, 기획 시 우선 고려)

- 몬티 홀류 확률 퍼즐: 베르트랑 상자 역설(Bertrand's box) — 몬티홀과 유사해서 시리즈 텀을 두고 배치
- 콜라츠 추측 (3n+1) — 아직 안 풀린 문제라는 미스터리 훅에 강함
- 이상한 나라의 벤포드류: 해안선 역설(coastline paradox) — 계단역설과 결이 겹치니 나중에
- 사라진 정사각형 퍼즐 — 시각 착시로 강력하지만 좌표를 정밀 검산해야 함 (섣불리 만들지 말 것)
- 두 봉투 역설(Two Envelopes) — 설명이 길어서 20초에 압축하기 까다로움, 대본 먼저 짧게 써볼 것
- 익스플로딩 닷츠(exploding dots) / 곱셈 시각화
- 뉴컴의 역설 — 철학적 색채 강해서 "과학" 느낌 약할 수 있음, 후순위
- 심슨의 역설류 실제 데이터 하나 더 (예: UC버클리 입학 성차별 사례) — 4번과 톤 겹치니 텀 두고

## 그동안 배운 것 (회차별 갱신)

- **1~9회차**: 매번 정확한 실제 수치로 검증하는 게 신뢰도의 핵심. 헤딩 텍스트에 % 넣으면 ffmpeg가 깨짐.
- **10~12회차**: ③긴장 피크(의심 대신 말해주기)를 의식적으로 넣으니 영상이 훨씬 탄탄해짐. 발산형(안 수렴하는) 반전도 로그축+계단식 그래프면 설득력 있게 보여줄 수 있음. 논리 퍼즐(힐베르트 호텔)은 통계적 검증 대신 "화면에서 충돌 없음을 직접 확인시키는" 방식으로 검증 단계를 대체 가능.
