# 데일리 릴스 자동화 (하루 3개, 트렌드 기반, 안 겹치게)

이 스킬은 **완전 자동**으로 끝까지 간다 — `reels-auto`(수동으로 주제 하나씩 요청받아 만드는
스킬)와 달리, 사람이 주제를 정해주지 않는다. 대신 오늘의 트렌드를 스스로 조사해서 3개를
고르고, 만들고, 커밋하고, 전달까지 한다.

## 0단계 — 환경 + 이력 확인
- `node_modules/playwright` 심볼릭 링크와 `ffmpeg`(libx264)가 있는지 확인한다. 없으면
  `.claude/hooks/session-start.sh`를 직접 실행해서 갖춘다(이 훅이 이미 세션 시작 시
  자동 실행됐어야 하지만, 혹시 몰라 한 번 더 확인).
- `reels/topics_log.json`을 읽는다. `episodes` 배열의 **최근 10개** 항목에서:
  - 이미 쓴 주제(topic_ko)와 시각적 기법(techniques) 태그를 뽑아 "최근에 쓴 것" 목록을 만든다.
  - `latest_cliffhanger`도 확인한다 — 오늘 트렌드와 잘 맞으면 이어가도 되지만, 매번
    이어갈 필요는 없다(사용자가 원한 건 다양성이지 시리즈 강제 연장이 아니다).

## 1단계 — 오늘의 트렌드 조사
`WebSearch`(deferred tool, 필요하면 `ToolSearch`로 로드)를 써서 **두 갈래를 모두** 검색하고,
그날그날 더 재밌는/영상화하기 좋은 쪽을 고른다:
1. **화제성 이슈**: 최근 수학/과학/우주 관련 뉴스, 화제가 된 발견·사건 (예: 새로운 소수
   발견, 우주 탐사 뉴스, 수학 난제 관련 소식 등)
2. **조회수 트렌드**: 유튜브 쇼츠/틱톡에서 요즘 잘 되는 수학 숏폼 주제나 포맷 (검색어 예:
   "math shorts viral", "수학 틱톡 화제", "math facts trending")

검색 결과에서 **3개의 서로 다른 소재**를 뽑는다. 이때:
- 오늘 세 개는 서로 겹치면 안 된다(같은 개념, 같은 실생활 사례 재탕 금지).
- 가능하면 0단계에서 뽑은 "최근에 쓴 주제/기법"과도 겹치지 않게 고른다.
- 검색으로 얻은 소재가 부실하면 억지로 끼워 맞추지 말고, `reels/README.md` 하단에 있는
  주제 후보나 스스로 판단한 "요즘 관심 가질 만한 수학 이슈"로 보충해도 된다 — 단,
  이 경우 나중에 사용자에게 보고할 때 "검색으로 못 찾아서 자체 판단으로 보충했다"고 밝힌다.

## 2단계 — 3개 모두 "안 지루하게" 만들기
같은 형식을 세 번 반복하면 바로 지루해진다. 3개를 고를 때 아래 세 축을 **서로 다르게**
섞는다(전부 같은 조합이면 안 됨):
- **장면 형식**: 기하 작도(도형이 그려지는 방식) / 타이포그래피(공식·숫자 중심) /
  팩트체크(주장→`drawStamp` 판정) / 프레임 단위 데이터 채우기(`prime_spiral.js` 참고) 중
  최소 2가지 이상을 오늘 3개에 나눠 쓴다.
- **주제 성격**: 순수 수학 개념 / 실생활·자연 연결 / 속설 팩트체크 중 섞는다.
- **브랜드 색상 배정**: `NEON` 팔레트 내에서 케이스별 색이 겹치지 않게 하는 기존 규칙은
  유지하되, 어떤 색을 "주인공 색"으로 쓸지도 매번 바꾼다.

각 영상은 `reels-auto` 스킬과 동일한 브랜드 골격을 따른다 — `reels/README.md`를 먼저 읽는다:
- 헤더(`drawHeader`) + 스텝카드(`drawStepCard`) + 진행바(`drawProgressBar`) + 77math
  로고(`drawBrandLogo`)
- 다이어그램 중심은 `SAFE_CX` 기준(안전영역), `WIDTH/2` 아님
- 20~25초, 호기심 유발 → 접근/전개 → 핵심 → (선택) 클리프행어 → 아웃트로
- `drawBurst`/`drawFlare`/`drawDust`/`drawOrbitRing` 등 기존 헬퍼를 적극 재사용하되,
  "화려하지만 매번 똑같은 연출"이 되지 않도록 매 영상 다른 조합을 쓴다.

## 3단계 — 제작 (3개 반복)
각 주제마다:
1. `reels/storyboards/<topic-slug>.js` 새로 작성 (기존 파일을 템플릿으로 참고, 복붙 금지 —
   최소 하나의 시각 기법은 최근 3~4개와 달라야 한다).
2. 빠른 확인: `node reels/render.mjs --story <slug> --out /tmp/<slug>_safe.mp4 --fps 5 --safe`
   로 안전영역 밖으로 나가는 게 없는지, 타이밍이 맞는지 확인. 문제 있으면 고치고 재확인.
3. 최종 렌더링은 **`reels/published/`에 바로** 저장한다(임시 폴더가 아니라 영구 보관 폴더):
   ```
   node reels/render.mjs --story <slug> --out reels/published/<YYYY-MM-DD>_<slug>.mp4 --fps 30
   ```
4. `ffprobe`로 길이(20~25초)와 해상도(1080x1920)를 확인한다.

## 4단계 — 이력 갱신 + 커밋 + 푸시
- `reels/topics_log.json`의 `episodes` 배열 끝에 오늘 3개를 추가하고 `latest_cliffhanger`를
  갱신한다(클리프행어를 안 만들었다면 이전 값을 유지하거나 null로 바꾼다).
- 스토리보드 코드 + `topics_log.json` + `reels/published/`에 새로 생긴 mp4 3개를 **하나의
  커밋**으로 묶어서 커밋하고 브랜치에 푸시한다. 커밋 메시지에 오늘 고른 3개 주제와 각각의
  트렌드 출처(뉴스 이슈 vs 조회수 트렌드)를 한 줄씩 적는다.

## 5단계 — 전달
- `SendUserFile`로 3개 mp4를 전달한다. 예약 트리거로 자동 실행된 경우 `status: "proactive"`를
  쓴다(사용자가 지켜보고 있지 않을 수 있으니).
- 채팅 응답에는 전체 코드를 다시 늘어놓지 않는다. 대신:
  - 오늘 고른 3개 주제와 각각 왜 골랐는지(어떤 트렌드/이슈에서 나왔는지) 한 줄씩
  - 3개가 서로 어떻게 다른지(장면 형식/주제 성격) 한 줄
  - `[확인필요]` — 실생활 사례나 뉴스 인용이 들어갔다면 게시 전 사실관계 재확인 권장을
    반드시 짚는다(이 스킬은 트렌드 검색 결과를 자동으로 소재 삼는 것이라, 블로그
    파이프라인의 5단계 검수 같은 사람 손 검증이 없다).

## 알아둘 점 (한계)
- 이 스킬을 예약 트리거(`CronCreate`)로 돌릴 경우, 세션이 살아있는 동안 + 최대 7일까지만
  자동 반복된다(플랫폼 제약). 7일을 넘어 계속 돌리려면 Claude Code 웹 UI에서 별도의
  "Trigger"(세션 자체가 아니라 플랫폼 차원의 예약)를 설정해야 한다 — 이건 도구 호출로 되는
  게 아니라 사용자가 UI에서 직접 설정해야 한다.
- WebSearch 결과의 사실관계는 이 스킬이 검증하지 않는다. 특히 "최근 이슈"류는 오검색/오래된
  정보일 위험이 있으니, 확신이 안 서면 영상에서 단정적으로 말하지 말고 완곡하게 표현한다.
